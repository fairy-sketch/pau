# Decisions

One line each: decision, then reason. Newest section at the bottom. The brief is `docs/BRIEF.md`.

## Approved by Ramon before M0 (16 Nov 2026)

| #   | Decision                                                                                                                                                                                                                    | Reason                                                                                                               |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| A1  | Stop and wait for Ramon's go after **every** milestone.                                                                                                                                                                     | Ramon's instruction overrides section 12 ("wait if the report needs a decision").                                    |
| A2  | `waitlist_entry` is the single source of truth for the waitlist. A `booking` row is created only on promotion; `booking.status` has no `waitlisted / offered / expired`. Applies from M2.                                   | The brief models the waitlist twice (booking statuses and `waitlist_entry`); two copies of one state drift apart.    |
| A3  | Admin over-capacity bookings carry an explicit, audited `is_override` flag that the "confirmed ≤ capacity" invariant excludes.                                                                                              | The brief requires both a hard capacity invariant and an admin override.                                             |
| A4  | Capacity counts `confirmed + held + pending_payment` bookings together.                                                                                                                                                     | The brief checks `booked_count < capacity` but also says holds count against capacity.                               |
| A5  | `mark_attendance` (SQL) and the `held` / `pending_payment` booking states are built in M2; their screens come in M6 and M7.                                                                                                 | The M2 no-show sweep and M4 attendance-to-log draft need attendance; the state machine should not be reshaped in M7. |
| A6  | `org_id` columns in the person layer (`recommendation`, `training_plan`, `coach_action_proposal`, `plan_item` references) are nullable references that never grant access. `coach_alert` gets its own club-readable policy. | Keeps the person layer outside any tenant while still pointing at club things.                                       |
| A7  | Background jobs run in a Node worker, not `pg_cron`. Identity in SQL is wrapped in one function (from M1) instead of calling `auth.uid()` everywhere.                                                                       | The brief asks for plain Postgres with no vendor-only features, so a later hosting move touches one place.           |
| A8  | Guests need a light account (email only) to claim a trial or buy a drop-in.                                                                                                                                                 | "Once per person" and a purchase both need an identity.                                                              |
| A9  | Stage four is called "Test". PAU's Saturday community session is its own offering. Gym session times are marked placeholders.                                                                                               | Resolves small inconsistencies in the brief (sections 5.1 vs 8.1, 7.1 vs M2).                                        |
| A10 | Fonts: **Archivo** (variable, expanded widths and italics) for display, **JetBrains Mono** for UI and data.                                                                                                                 | Both free (OFL). Archivo has the extended italic the brief describes; Unbounded has no italic.                       |
| A11 | Built in the cloud workspace, pushed to `github.com/fairy-sketch/pau`. Local Supabase is verified on Ramon's machine.                                                                                                       | Docker is not available in the cloud workspace.                                                                      |
| A12 | "Installs as a PWA on a phone" is verified by automated installability checks plus manual steps in the README.                                                                                                              | A real phone cannot be driven from the build environment.                                                            |

## M0. Foundations

| #   | Decision                                                                                                                                                                                   | Reason                                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | The brief is stored as `docs/BRIEF.md`.                                                                                                                                                    | The uploaded file was named `claude-code-prompt.md`; Ramon refers to it as BRIEF.md.                                                 |
| 2   | Versions: Next.js 16.4 (App Router, Turbopack), React 19.3, TypeScript 5.9, Tailwind 4.3, next-intl 4, Zod 4, Vitest 5, Playwright 1.63. pnpm is the package manager.                      | Current stable releases at project start. TypeScript 7 is out but the lint toolchain still targets 5.x.                              |
| 3   | `app/` sits at the repo root and modules under `src/`, imported as `@/src/...`.                                                                                                            | Matches the structure in section 11.                                                                                                 |
| 4   | Next's `cacheComponents` and `partialPrefetching` stay on (the scaffold default).                                                                                                          | They give a prerendered app shell that keeps working through connectivity drops, which the Path and coach roster need later.         |
| 5   | Tailwind 4 tokens live in `app/globals.css` (`@theme`). Tailwind's default colours and radii are removed, so only our tokens can be used.                                                  | "No default look" enforced by the build, not by discipline.                                                                          |
| 6   | Components use semantic tokens (`bg`, `fg`, `muted`, `rule`, `accent`) that switch per surface (`data-surface="ink"` / `"paper"`). `accent` reads `--org-accent`, default `accent-signal`. | Lets a section invert, and lets a club set its own accent later without touching components.                                         |
| 7   | Accent fills always carry white text. `accent-electric` is never text on black; `accent-signal` on black is for large display type only.                                                   | Those are the pairs that pass WCAG AA; a unit test checks every allowed pair at 4.5:1.                                               |
| 8   | Fonts are self-hosted from the `@fontsource-variable` packages, not loaded from Google.                                                                                                    | No third-party request from members' phones (nDSG, privacy by design), and the build works offline.                                  |
| 9   | Display type scales with the viewport and may break inside a word as a last resort.                                                                                                        | A long single word in extended black type otherwise pushes the page sideways on a phone.                                             |
| 10  | The focus ring is the current text colour, not an accent.                                                                                                                                  | Stays visible on both white and black surfaces.                                                                                      |
| 11  | The ticker has a pause button and does not move under reduced motion.                                                                                                                      | WCAG 2.2.2 (moving content must be pausable) and the brief's reduced-motion rule.                                                    |
| 12  | The stage track scrolls sideways on narrow phones; state is shown by line style and label, not colour alone.                                                                               | Five labelled stages do not fit 390 px legibly; colour-only state fails accessibility.                                               |
| 13  | Charts use Recharts, restyled (square markers, dotted rules, mono axes, no animation), with the data repeated as a screen-reader table.                                                    | Brief allows visx or Recharts; Recharts supports React 19 out of the box. The SVG alone is not accessible.                           |
| 14  | UI components in `src/ui` take already-translated strings as props; pages do the translating.                                                                                              | Keeps the design system free of i18n wiring and usable in server and client components.                                              |
| 15  | Single-locale next-intl setup: catalogue `en.json`, formatting locale `en-CH`, time zone `Europe/Zurich`, no locale in the URL. Message keys are type-checked.                             | English only in v1, but adding DE/FR is a change in `src/i18n/request.ts`, not a rewrite.                                            |
| 16  | "No hardcoded UI strings" is enforced twice: ESLint `react/jsx-no-literals` for JSX text, and a unit test for text attributes (`aria-label`, `alt`, `title`…).                             | The lint rule skips attributes. Both checks were confirmed to fail on a planted violation.                                           |
| 17  | A unit test fails if the product name is written anywhere except `APP_NAME` in `src/config/app.ts`.                                                                                        | The brief requires renaming in one place.                                                                                            |
| 18  | Service worker: Serwist via `@serwist/turbopack`, served at `/serwist/sw.js`, with a precached `/offline` fallback page.                                                                   | Serwist is the brief's first choice; this is its supported setup for Turbopack builds.                                               |
| 19  | PWA icons are generated from an SVG mark by `pnpm icons` (placeholder mark: two leaning lanes).                                                                                            | No logo exists yet; regenerating is one command when it does.                                                                        |
| 20  | Job queue = one `job` table plus SQL functions (`enqueue_job`, `claim_jobs`, `complete_job`, `fail_job`), claimed with `FOR UPDATE SKIP LOCKED`, behind a `JobStore` interface.            | Plain Postgres, safe with several workers, and swappable as the brief asks.                                                          |
| 21  | Jobs retry with exponential backoff (30 s doubling, max 1 h) up to 5 attempts, then become `dead`. A job stuck `running` for 10 minutes is reclaimed.                                      | A crashed worker or a flaky dependency must not lose or endlessly spin a job.                                                        |
| 22  | Recurring jobs are enqueued with a dedupe key per time slot.                                                                                                                               | Several workers, or a restart, never create the same job twice.                                                                      |
| 23  | The `job` table has RLS enabled (not forced) with no policies, and privileges revoked from `anon` and `authenticated`. The worker connects directly as the table owner.                    | It is infrastructure, not tenant data. Forced RLS (required for club tables) would lock the owner out too.                           |
| 24  | SQL is unit-tested in-process with PGlite (real Postgres compiled to WASM), with Supabase's API roles created by the test helper.                                                          | Proves migrations and SQL functions without Docker. RLS tests that depend on Supabase Auth run against the real local stack from M1. |
| 25  | `pnpm test` = lint + format check + typecheck + unit tests (no external services). `pnpm test:e2e` = Playwright against a production build. `pnpm test:all` = both.                        | `pnpm test` must run anywhere in seconds; the browser tests need a build and installed browsers.                                     |
| 26  | The Playwright "mobile" project uses the iPhone 14 profile on Chromium by default; `PW_WEBKIT=1` switches it to WebKit.                                                                    | Only Chromium is installed in the build environment. The profile (viewport, touch, user agent) is what the tests depend on.          |
| 27  | Accessibility is checked automatically with axe (WCAG 2.2 AA rules) on every page in the e2e run.                                                                                          | The brief sets WCAG AA; catching regressions from M0 is cheaper than a late audit.                                                   |
| 28  | No GitHub Actions workflow yet; CI is the `pnpm test` script.                                                                                                                              | The brief asks for a CI script. A hosted workflow needs a decision on where Supabase runs in CI.                                     |
| 29  | Supabase CLI is a dev dependency (`pnpm db:start`), Postgres 17.                                                                                                                           | Setup from a clean clone needs no global installs beyond Node, pnpm and Docker.                                                      |
